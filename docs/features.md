# dsh-md-notes 功能设计文档

本插件为 DSH 提供 **MD 笔记管理**：在侧边栏常驻入口，打开全屏笔记管理界面；
并允许把任意一条回答及其提问直接记入指定笔记。

## 1. 功能总览

| 功能 | 入口 | 说明 |
|---|---|---|
| 打开笔记管理 | 侧边栏 📓 笔记入口 | 全屏面板：左侧列表 + 右侧编辑/预览 |
| 新建笔记 | 管理界面顶部输入框 + 「新建」 | 空标题自动用"未命名笔记 日期" |
| 编辑笔记 | 管理界面右侧「编辑」Tab | markdown 源码编辑，点「保存」写入 |
| 预览笔记 | 管理界面右侧「预览」Tab | 内置轻量 markdown 渲染器 |
| 删除笔记 | 列表项 🗑 | `confirm` 确认后删除文件 |
| 记入笔记 | 每条回答下方的 📝 | 选择目标笔记，追加该回答及提问 |

## 2. 功能详述

### 2.1 侧边栏入口（📓 笔记）

- 位置：左侧栏**底部区域最上一行**，独占一行，在 Cordis 插件徽章上方、设置下方。
- 宽栏显示"📓 笔记"，折叠成 56px 窄栏时显示圆形 📓 图标。
- 点击打开笔记管理全屏面板（`shell.overlay`）。
- 实现细节：入口行通过 JS 在挂载时给父 flex 容器设 `flex-wrap: wrap` 并置 `order: -1`，
  保证独占一行且排在最上（见 `src/client/index.tsx` 的 `NotesEntry`）。

### 2.2 笔记管理界面

布局：全屏遮罩 + 居中面板（`shell.overlay` 注册），分左右两栏。

**左栏 — 笔记列表**
- 展示每篇笔记的标题与更新时间（按更新时间倒序）。
- 顶部输入框 + 「新建」按钮：输入标题创建；留空自动用"未命名笔记 <日期>"。
- 列表项：点击打开右侧编辑；🗑 删除（`confirm` 确认）。

**右栏 — 编辑器**
- 「编辑 / 预览」双 Tab：
  - **编辑**：textarea 编辑 markdown 源码；
  - **预览**：内置渲染器输出 HTML（先 HTML 转义再渲染，防注入）。
- 「保存」按钮：写入当前内容，刷新列表，短暂提示"已保存"。

### 2.3 记入笔记（📝）

- 每条已完成的回答下方操作行（复制/点赞那一行）有一个 📝 图标。
- 点击弹出选择面板（`shell.overlay`）：
  - 列出已有笔记（单选）；
  - 可现场新建一篇（输入标题 + 「新建」）；
  - 点「写入笔记」→ 把**该回答对应的用户提问 + 回答内容**格式化后**追加**到选中笔记末尾。
- 追加内容格式：

  ```markdown
  ---

  ## <时间戳> · <会话标题>

  **用户**：
  <提问内容>

  **DSH**：
  <回答内容>
  ```

## 3. 交互状态与反馈

| 场景 | 反馈 |
|---|---|
| 新建成功 | 列表刷新 + 自动打开新笔记 + 提示"已创建 ✓" |
| 保存成功 | 提示"已保存"（1.2s 后消失） |
| 写入笔记成功 | 提示"已写入 ✓"，900ms 后自动关闭弹窗 |
| 任一操作失败 | 面板/弹窗内显示具体错误信息（如"创建失败: …"） |
| 删除 | 原生 `confirm` 确认框 |

## 4. 数据模型

笔记 = 工作区 `.dsh-notes/` 下的普通 `.md` 文件：

```
.dsh-notes/
├── <note-name>.md      # 笔记内容（markdown）
└── meta.json           # { "<note-name>.md": { title, updatedAt } } 标题与更新时间缓存
```

- 文件名由标题规范化而来（非法字符转 `-`，强制 `.md` 后缀），重名自动加序号。
- `meta.json` 为最佳努力缓存：缺失或损坏时按文件名回退标题，不影响读写。
- 目录位置可配置（`config.root`），默认 `<cwd>/.dsh-notes`。

## 5. 非功能需求

- **普通文件可访问**：笔记就是 `.md` 文件，用户可直接在文件系统编辑，插件下次读取即生效。
- **无外部依赖**：Host/Client 通信走插件自带 HTTP 路由，不依赖 typert/Remote 工具链。
- **主题适配**：样式使用 DSH 主题 CSS 变量（`--dsw-alias-*`）并带静态兜底，明暗主题均可读。
- **HMR 安全**：所有副作用（路由注册、样式注入、slot 注册）均挂在 `ctx.effect` 上，卸载时自动清理。

## 6. Git 同步（规划中）

让笔记可提交到 Git 仓库同步（GitHub/GitLab 等）。仓库组织采用**统一模型**：

- 每个 dsh 工作区**最多一个独立仓库**（可选，工作区内默认无需授权）；未配置独立仓库的
  工作区**默认用总仓库**——但**总仓库默认不启用**：它位于沙箱之外，需在设置面板配置路径并
  **授权**（approval 审批）后才生效（见 [git.md](git.md) §2.3）；
- **总仓库**一个，收纳所有工作区的笔记，每个工作区一个**以工作区名命名的文件夹**
  （工作区改名时，总仓库内目录跟随改名，保留提交历史）。

设置项采用**三层配置模型**：cordis Config（部署级 yaml）→ settings 命名空间 `md-notes`
（用户级，设置面板/笔记同步区 UI 编辑）→ 生效值逐层合并。完整设计见
[git.md](git.md)（设置项总表、仓库模型与目录布局、API/UI 设计、实现要点）。

**交互模型**（git 开启后）：

- **保存** = 笔记写入本地文件（不碰 git）；**推送** = **整个仓库** commit + push（先弹 commit
  面板，推送后自动回拉）；**更新** = **整个仓库**拉取远端版本。
- **左侧面板按工作区展示**：每个工作区头部有「更新 / 推送」按钮（单工作区仓库级）。
- **编辑器头部**（工作区配置了仓库时）：「保存」左侧出现「更新」、右侧出现「推送」
  （作用于该工作区仓库）；总仓库已配置时管理器头部（关闭按钮左侧）另有**全局**「更新 / 推送」。
- 打开笔记时自动拉取远程版本（设置 `gitAutoPull`，默认开启）。
