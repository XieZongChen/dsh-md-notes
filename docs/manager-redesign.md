# NotesManager 改版方案

> 目标：解决当前笔记面板「工作区级 Git 同步」与「笔记级保存」两个层级的操作混杂、scope 不清晰的问题；同时为未来功能（搜索 / TOC / 反链 / 冲突对比 / 快捷访问）预留布局位置。
>
> 设计参考：`markdown-notes-manager-design` 系列程序化设计稿（浅色 + `--dark` 深色两版，含状态色、三栏布局、全宽工具栏等）。

## 1. 背景与问题

现状（`src/client/features/NotesManager/NotesManager.tsx`）：

- 「更新 / 推送」同时出现在**工作区行**（`wsIconBtn`）和**编辑器工具栏**（`gitBtn`）两处；
- 编辑器工具栏里「保存（笔记级）」和「更新 / 推送（工作区级 Git）」并排混在一起；
- 底部 `syncLine` 又重复展示分支 / 未提交等 Git 状态；
- 三处分散，用户分不清「哪些操作只影响这篇笔记、哪些影响整个工作区」。

## 2. 设计原则

1. **层级分离**：笔记级操作（编辑 / 预览 / 保存 / 删除 / 未保存）只在编辑器工具栏；工作区级 Git（更新 / 推送 / 状态）只在工作区 Git 卡片；两者用位置 + 配色彻底隔开。
2. **状态色语义**：绿 = 已同步 / 已保存 / 已连接；琥珀 = 未推送 / 未保存；蓝 = 主色 / 激活；红 = 删除 / 危险。
3. **分阶段**：先落「层级分离」这个核心痛点（P0），搜索 / TOC / 反链 / 冲突视图等未来功能只**预留位置**（P1 / P2）。

## 3. 目标布局

三栏 + 底栏（面板从 980px 加宽到 ~1280–1440px）：

```
┌──────────────────────────────────────────────────────────────────┐
│ 顶部栏：图标 + 笔记管理器 + ⚙设置      [搜索框 · 未来]            │
├───────────────┬────────────────────────────────┬─────────────────┤
│ 左栏 (300)    │ 编辑器 (flex)                   │ 右栏 (300·预留) │
│ 快捷访问(预留) │ ┌─ 全宽工具栏 ────────────────┐ │ 本文目录 (未来) │
│ 工作区 A      │ │ [预览|编辑]  未保存 删除 保存 │ │ 反链 (未来)     │
│  ├ 笔记列表   │ ├──────────────────────────────┤ │                 │
│  └ Git 卡片   │ │ 面包屑 + 文件名               │ │                 │
│ 工作区 B(折叠)│ │ markdown 正文                 │ │                 │
│ + 新建工作区  │ │                               │ │                 │
├───────────────┴────────────────────────────────┴─────────────────┤
│ 底栏：Git 同步 · 全局 · 未推送 N 处          所有更改已保存        │
└──────────────────────────────────────────────────────────────────┘
```

> 右栏、搜索、快捷访问均为未来功能，本次只占位，不做真实数据。

## 4. 具体改造点

### 4.1 顶部栏
- **保留**：标题「笔记管理器」、设置按钮（`IconSettingsOutline16`，齿轮，紧挨标题右侧，现有位置不动）、右上角关闭按钮（`IconCloseOutline16`）。
- **去掉**：全局「新建笔记」按钮（新建改为工作区行尾的 `+`，见 4.2）。

### 4.2 左栏工作区行（`.wsGroupHead`）
- **保留**：文件夹图标、折叠箭头、工作区名、笔记数、`+` 新建（复用现有 `IconPlusOutline16`，放在行尾、折叠箭头左侧）。
- **去掉**：状态 chip（已同步 / 未推送）、更新 / 推送 icon 按钮（`wsIconBtn`）。
- 顺序（左→右）：文件夹 → 名称 → 数量 → `+` → 折叠箭头。

### 4.3 左栏 Git 同步卡片（新组件 `GitSyncCard`）
- **位置**：每个工作区组内、笔记列表之后（无仓库 `!status.repoDir` 时不渲染）。
- **内容**：标题「Git 同步 · 整个工作区」+ 状态 pill（已同步 / 未推送 N 处）+ 分支 / 子路径 / 上次提交 / 未提交数 + 「更新（拉取）」「推送（提交）」两个按钮 + 冲突提示位。
- **复用**现有 `gitStatusApi` → `statusByWs`、`updateClick`、`pushForWs`、`doPush` 逻辑，不改 host。

### 4.4 编辑器工具栏（`.editorHead`）
- **全宽**：横跨编辑器 + 目录列，直到面板右缘（贯穿出去）。
- **Tab 顺序**：预览在左（激活态）、编辑在右。
- **右对齐**：未保存 pill + 删除 + 保存；保存是唯一主色实心按钮，放最右。
- **去掉**：更新 / 推送 `gitBtn`（移到 Git 卡片）。

### 4.5 笔记元信息
- **保留**：面包屑（工作区 / 标题）+ 文件名 chip。
- **去掉**：绿色「已连接」git chip。

### 4.6 右栏（预留）
- 「本文目录」「谁引用了它」——未来 TODO 4.2 / 4.3。
- 本次只占位，且**顶部对齐正文 h1**，不顶到面板顶部。

### 4.7 底部状态栏（`.syncLine` → 全局）
- 语义改为**全局聚合**：「Git 同步 · 全局」+「未推送 N 处」（跨工作区求和，琥珀）+「X 个工作区 · Y 个待同步」。
- **不显示**单个工作区的分支 / 上次提交（那些属于 Git 卡片）。
- 右侧保留「所有更改已保存」/ busy 指示；冲突提示就近放 Git 卡片或底栏。

## 5. 细节规范（实现时不要照搬设计稿的手算坐标）

设计稿是脚本手写 x/y 画的，间距 / padding 不准；真实实现一律用 **flex gap + 统一尺寸 token**：

| 项 | 规范 |
|---|---|
| 按钮之间间距 | 统一 `gap: 8px`；右对齐用 `margin-left: auto` |
| 主按钮（保存 / 新建 / 推送确认） | `height: 32px; padding: 0 16px; border-radius: 8px` |
| 次级按钮（更新 / 删除 / 取消） | `height: 32px; padding: 0 12px; border-radius: 8px` |
| 图标按钮点击区 | 视觉 16px、点击区 ≥ 28×28px（现 `wsIconBtn` 16×16 偏小） |
| 按钮内 icon ↔ 文字 | `gap: 6px` |
| pill（未保存 / 已同步 / 未推送） | `height: 20–22px; padding: 0 10px; border-radius: 999px` + 左侧 4px 圆点 |
| 删除按钮 | 红描边 `danger` 样式，常驻编辑器工具栏 |
| 编辑器内容 padding | `14px 18px`（保留现状） |

## 6. 状态与数据

| 能力 | 归属 | 说明 |
|---|---|---|
| `dirty`（未保存） | `NotesManager` 本地 state | `content` vs 上次保存快照比对；切换 / 关闭前提醒（未来 5.3） |
| 全局未推送计数 | `NotesManager` `useMemo` | 由 `statusByWs` 聚合求和，不改 store |
| 快捷访问 / 搜索 / TOC / 反链 | 未来 | 见 TODO 4.x，本次只占位 |

## 7. 分阶段落地

1. **P0（核心层级分离）**：§4.1–4.5 + §4.7 + §5，改动集中在 `NotesManager.tsx` + `notes-manager.module.css`。
2. **P1**：搜索框 UI + 快捷访问空态 + 底部全局计数（真实数据 + 预留位）。
3. **P2**：右栏 TOC / 反链、Git 冲突并排对比（依赖 host 新 API，按 TODO 3 / 4 单独排期）。
