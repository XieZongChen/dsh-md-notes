### 2.2 引用笔记的样式优化（待做）

**目标**：把「笔记引用」在三个展示面上的观感从「能用」提升到「好看、可识别」。

**现状**：

- 输入框 chip：dsh 硬编码胶囊（蓝底、原生 4em 单元格），插件已做标签前置截断（>4 字符 → 前 4 + …）；
- 发送后的消息行：纯文本 `引用笔记「标题」：.dsh-notes/xxx.md`（dsh 用户气泡是纯文本渲染，
  无法内联自定义样式）；
- 注入上下文行：通用「上下文注入」DisclosureRow（来源标 `md-notes`），无笔记专属外观。

**设想**（各受 dsh 渲染机制约束，见 context.md §2.1/§3.3/§3.7）：

1. **输入框 chip**：
   - 跨工作区引用的 chip 能看出工作区来源（如标签带 `工作区·` 前缀，或 hover tooltip 显示完整路径）；
   - 截断上限按 chip 实际像素宽自适应（当前 6 字符对中英混排偏保守）。
   - 受限点：chip DOM 为 dsh 硬编码（`InputBar`），尺寸 4em 固定；曾用 `DshChipCell` 字体覆盖
     放大（6em/10em），按平台「不注入核心样式」规范已移除——后续若要更大标签区，需平台开放
     chip 尺寸或渲染扩展点。
2. **发送后的消息行**：
   - 探索与 dsh 已有的 `/name`、`@name` 词元 chip 渲染（`projectUserText` 的 `refChip`）对齐——
     例如序列化格式能否让路径以可识别词元呈现，获得原生高亮样式；
   - 或等 dsh 提供用户消息内容块的渲染扩展点后再做自定义行内卡片。
3. **注入上下文行**：
   - 来源标签显示**笔记标题**而非 `md-notes`（受 `contextProvenance` 的 kind 映射约束，
     需在 source 里携带标题字段或选用 dsh 已有 form/provenance 通道）；
   - 行内摘要（标题 + 前 N 字）与更贴合的图标/配色（当前走通用 `OpaqueBody`）。
   - **手动删除持久化**：注入的笔记内容会一直留在会话历史里（直到 compaction）。
     在注入上下文行上加「删除」按钮：host 新增 API（如 `contextRemove(sessionId, path)`），
     按 `source.kind === 'md-notes'` + `path` 定位该消息，用 surface `{ op: 'replace', start, end }`
     把它从模型可见历史中移除（compaction 同款机制）；只删注入内容、不动用户自己的消息；
     删除后不会复活（pre-step 只扫描新提交消息找引用）。

**验收标准**：三个展示面都能一眼识别「这是一篇笔记引用」及其来源工作区/标题；
明暗主题下样式一致；不破坏现有引用功能（候选/chip/注入）。

## 3. Git 冲突渲染及可视化解决

**目标**：推送/更新遇到 git 冲突时，不再只给纯文本错误，而是可视化展示并引导解决。

**设想**：

- 冲突检测已具备（`remote-changed`、`non-fast-forward` 错误码）；在此基础上：
  - **冲突渲染**：在管理器内渲染冲突笔记的对比（远端 vs 本地），可逐文件查看差异。
  - **可视化解决**：提供「用远端」「用本地」「合并」等操作入口（现有确认弹窗升级为冲突面板）。
  - 合并（`gitSync`）的结果展示合并状态与剩余冲突。

**验收标准**：推送/更新遇冲突时，管理器展示冲突列表与差异视图，用户可逐项选择保留/合并。

## 4. Markdown 能力增强

**目标**：把内置轻量渲染器升级为覆盖笔记常见语法的渲染能力，提升笔记预览体验。

**现状**（`src/client/features/markdown.ts`，纯函数；先 HTML 转义再渲染子集，XSS 安全）：

- 已支持：标题 h1–h6、无序列表、围栏代码块（不识别语言）、引用（单行）、hr、
  行内代码 / 粗体 / 斜体 / 链接。
- 缺失/受限：有序列表、任务列表（`- [ ]`）、表格、图片、删除线、多行引用合并、
  嵌套列表、代码块语言标注；标题无锚点 id，无法在预览内精确跳转。

**设想**：

- **语法补齐**：有序列表（连续 `1.` 行合并为 `<ol>`）、任务列表（`- [x]` 复选框）、
  GFM 表格、图片 `![alt](url)`、删除线 `~~x~~`、多行引用块合并、按缩进嵌套列表、
  围栏代码块语言标注（`` ```ts `` → 代码块加语言类名，便于按语言着色 / 复制）。
- **标题锚点 id**：渲染时给标题生成稳定 slug 锚点，预览区内可跳转；并作为
  「@ 引用笔记」定位到**具体标题**的锚点基础（与使用文档「链接详细到标题」的引用风格一致）。
- **安全约束**：保持「先转义、后渲染子集」的模型，不引入原始 HTML 透传；新增语法
  全部基于转义后的纯文本解析。
- **配套测试**：渲染器是纯函数，增强后补 vitest 用例（「输入 markdown → 期望 HTML」
  表格化用例 + XSS 用例），防止后续改动破坏渲染（原「解析测试」项并入此处）。

**验收标准**：预览能正确渲染表格 / 任务列表 / 有序列表等新增语法；标题可锚点跳转；
  渲染保持 XSS 安全；新增语法均有测试用例覆盖。
