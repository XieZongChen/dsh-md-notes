## 2. 笔记加入 dsh 对话上下文（可被引用）

**目标**：把笔记作为可引用的上下文注入 dsh 对话，让模型在回答时能利用笔记内容。

**状态**：✅ 已实现（0.3.0）：`@` 引用候选菜单 / chip / 提交序列化路径引用（同工作区
`.dsh-notes/xxx.md`、跨工作区 `../<目录>/…`），host 端 `agent/pre-step` 把笔记内容注入模型
请求（不依赖模型自觉 `read`）；跨工作区 `@工作区名/`（ASCII，尾斜杠可选）+ 部分名字工作区行
自动补全；引用失效阻断发送并提示。设计见 [context.md](context.md)。

**实现**：

- 通过 dsh 的 `ui-input-trigger` 注册 `@` source（`features/ContextSource/`）：
  `candidates` 默认当前工作区笔记、`@工作区名` 或部分名字工作区行切换跨工作区；
  `onPick` 插入 chip（`ref` = 会话工作区相对路径）；`codec.serialize` 提交时输出
  路径引用、笔记缺失时阻断发送。
- host `context-inject.ts`：`agent/pre-step` 读取被引用笔记并注入模型请求（§3.7）。
- 与「记入笔记」形成闭环：对话可写入笔记，也可引用笔记进上下文。

**验收标准**：会话中引用笔记后，模型回答能引用笔记内容；引用入口与交互符合 dsh 现有模式。
⏳ 待真实会话联调确认（模型 `read` 读取并引用）。

### 2.2 引用笔记的样式优化（待做）

**目标**：把「笔记引用」在三个展示面上的观感从「能用」提升到「好看、可识别」。

**现状**：

- 输入框 chip：dsh 硬编码胶囊（蓝底），插件已做 6em 单元格放大 + 标签前置截断（>6 字符 → 前 6 + …）；
- 发送后的消息行：纯文本 `引用笔记「标题」：.dsh-notes/xxx.md`（dsh 用户气泡是纯文本渲染，
  无法内联自定义样式）；
- 注入上下文行：通用「上下文注入」DisclosureRow（来源标 `md-notes`），无笔记专属外观。

**设想**（各受 dsh 渲染机制约束，见 context.md §2.1/§3.3/§3.7）：

1. **输入框 chip**：
   - 跨工作区引用的 chip 能看出工作区来源（如标签带 `工作区·` 前缀，或 hover tooltip 显示完整路径）；
   - 截断上限按 chip 实际像素宽自适应（当前 6 字符对中英混排偏保守）。
   - 受限点：chip DOM 为 dsh 硬编码（`InputBar`），只能改字体宽度（`DshChipCell` 覆盖）与标签文本。
2. **发送后的消息行**：
   - 探索与 dsh 已有的 `/name`、`@name` 词元 chip 渲染（`projectUserText` 的 `refChip`）对齐——
     例如序列化格式能否让路径以可识别词元呈现，获得原生高亮样式；
   - 或等 dsh 提供用户消息内容块的渲染扩展点后再做自定义行内卡片。
3. **注入上下文行**：
   - 来源标签显示**笔记标题**而非 `md-notes`（受 `contextProvenance` 的 kind 映射约束，
     需在 source 里携带标题字段或选用 dsh 已有 form/provenance 通道）；
   - 行内摘要（标题 + 前 N 字）与更贴合的图标/配色（当前走通用 `OpaqueBody`）。

**验收标准**：三个展示面都能一眼识别「这是一篇笔记引用」及其来源工作区/标题；
明暗主题下样式一致；不破坏现有引用功能（候选/chip/注入）。

## 3. Git 冲突渲染及可视化解决

**目标**：推送/更新遇到 git 冲突时，不再只给纯文本错误，而是可视化展示并引导解决。

**设想**：

- 冲突检测已具备（`remote-changed`、`non-fast-forward` 错误码）；在此基础上：
  - **冲突渲染**：在管理器内渲染冲突笔记的对比（远端 vs 本地），可逐文件查看差异。
  - **可视化解决**：提供「用远端」「用本地」「合并」等操作入口（现有确认弹窗升级为冲突面板）。
  - 合并（`gitSync`）的结果展示合并状态与剩余冲突。

**验收标准**：推送/更新遇冲突时，管理器展示冲突列表与差异视图，用户可逐项选择保留/合并。

## 4. Markdown 解析测试

**目标**：为笔记的 markdown 渲染与领域逻辑补上自动化测试，防止解析器改动破坏现有渲染。

**范围**：

- `src/client/features/markdown.ts`（渲染器，纯函数）：标题 / 无序有序列表 / 引用 / 代码块 /
  内联样式（粗体、斜体、行内代码、链接）/ HTML 转义（XSS 安全）等输入→HTML 快照或断言。
- `src/host/notes.ts`（领域逻辑，纯函数）：`sanitizeName`（非法字符、保留名）、`titleOf`（元数据缺失回退）、
  `blocksToText`（reasoning 引用块 / image 占位）、`appendConversation` 的分段格式。

**方案**：

- 引入 `vitest`（与 deepseek-harness 测试栈一致），加 `npm test` 脚本。
- 渲染器用例：一组「输入 markdown → 期望 HTML」的表格化用例；XSS 用例单独一组。
- 领域逻辑用例：目录/文件操作用临时目录（`fs.mkdtemp`）跑真实读写，断言文件内容与 `meta.json`。
- 可选：渲染器做快照测试（vitest `toMatchSnapshot`），变更时人工确认 diff。

**验收标准**：`npm test` 全绿；新增/修改解析规则时，先加用例再实现。
