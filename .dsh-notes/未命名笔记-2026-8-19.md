## 问题根因

`assistantText` 是按模型 content 数组的**原始流顺序**拼接的（dsh 的 `blocks()` 按流式块到达顺序组装 content）。dsh 界面上 Think 显示在回答**上方**，但部分 provider 的 reasoning 块可能在 text 块**之后**才流式到达——导致记入时 content 数组是 `[text, reasoning]`，拼接出来就是「回答在前、思考在后」。

## 修复

`blocksToText` 把 reasoning 块**单独收集、固定排在所有正文之前**：

```
**💭 思考**
<思考内容（原样）>
**💭 思考结束**

<回答内容>
```

- 无论模型流的块顺序如何，记入后都是**先思考、再回答**——与 dsh 界面（Think 在上、正文在下）一致
- 思考内容仍然原样保留（不做逐行变换）
- 已用反序 content（`[text, reasoning]`）验证输出正确

## 需要你做的

重启 dsh web + 硬刷新，记入一条回答确认：笔记里思考块在回答上方（💭 思考 … 💭 思考结束 → 回答内容）。如果某篇笔记还是思考在后，说明是历史笔记（已按旧顺序写入），新记入的都会正确。
